# Retraining log: every fine-tuning run, and why it was done

Running record of every training run on the student model (Qwen2.5-7B-Instruct), what was changed each time, why, and
what came of it. Same layout as `FAILURE_LOG.md`: newest first, update the status column when a run is judged.
Settings are from `drive/runs/<run>/train_summary.json`; numbers are from `TRAINING.md`, `drive/SCORES_*.json` and
`docs/MODEL_CARD.md`. Where a date is not recorded it says so.

**How a run is judged.** First, **held-out loss** on the 89 test drafts and 50 test extractions (adapter against the
base model's 1.84 and 0.148): it must beat the base before any seed or ablation run is spent. Second, **greedy
predictions** scored for loops, own-fact use, distractor use, invented figures and dates, and extraction precision and
recall. Held-out loss alone can not choose between runs (every SFT run lands near 1.28 to 1.32); the loop count and the
fact-use measures decide.

**Base for every run:** Qwen2.5-7B-Instruct trained as 4-bit QLoRA with Unsloth, loss on the assistant turn only,
max sequence 6,144 tokens. Rank and alpha below are the LoRA settings.

## Considered, tested and not retrained (so nobody repeats them)

* **Decoding fixes instead of retraining:** low-temperature sampling (0.3) 34 loops against 38; repetition penalty 1.05 on a
  merged model 31 (invalid, see next); frequency penalty 0.3 on run A 23 loops. Only DPO plus the frequency penalty got to 1-4.
* **Merged weights:** merging an adapter trained on the 4-bit base into bf16 weights broke the model (found 4 Nov 2026), so
  every `predictions_test_merged*.jsonl` is invalid. Adapters are served unmerged on the bf16 base.
* **Context length:** trained at 6,144 tokens. The endpoint now allows 32,768 (the base model's native length) without
  retraining; behaviour beyond 6,144 was checked with one needle test only (a fact in a 12,000-token prompt was found).
* **Cleaning loops from the targets:** only 8 of 657 drafting targets repeat a 5-word opening 5 or more times, so loopy
  targets do not explain the loops.

## What a future retrain should change (not yet done)

* **Run 14 left:** 0 of 89 flagged after the repaired guard and metric (a tie with the base, not a win), 0.61 masked values per draft against the base's 0.65, and only 89 test drafts from 75 companies: a gap of one or two drafts is not a result. Raw single drafts still invent figures in 11% of cases and loop in 8%, so the guard and the loop cut stay mandatory. A second round of on-policy pairs (sampled from A_qa3_dpo3) is the next step if more is wanted.

* **Abstention without over-abstention (runs 11 to 13, 20 Nov 2026).** Showing the model gaps filled with `[●]` works in the
  direction wanted (raw invented figures 24.7% to 9% single draft) but a preference step with only abstention pairs teaches
  "prefer `[●]`" (run 12) and adding the mirror pairs over-corrects the other way (run 13). Next try: fewer abstention rows
  (about 15% of drafting rows, not 50%), a smaller DPO step (lr 5e-6 or one epoch) and a balanced pair set judged on the
  app-format prompts at best-of-3, where the choice between the two is a trade of fact use against masked values.

* **Invented plain text.** Business-narrative drafts (19 Nov 2026 dry run) still invent details the figure, date and name
  checks can not see (an address, a customer list before the organisation-name mask). A retrain would need training rows
  where the input holds the issuer's own business text, and DPO pairs against unsupported claims, not only against loops.
* **Longer inputs.** Rows with the issuer's own text passages as facts (how the app now prompts "Our Business") are not in
  the training data; the prompt format differs from training.
* **A second reviewer.** No run was compared by a practising DRHP reviewer on blind drafts; that needs the project owner.
